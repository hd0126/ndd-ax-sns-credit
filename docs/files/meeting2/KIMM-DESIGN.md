# KIMM Design MD — 한국기계연구원 문서 디자인 시스템

> \*\*버전\*\* v1.1 · \*\*준거 양식\*\* `보고서\_양식\_50주년\_1p.hwpx` · `KIMM\_보고서양식.docx`
> \*\*적용 대상\*\* 한글(HWPX)·워드(DOCX) 문서
> \*\*사용법\*\* 이 파일을 생성형 AI(ChatGPT·Gemini·Claude 등)에 업로드하거나 붙여넣은 뒤, 만들 문서를 말하면 됩니다.
> \*\*예:\*\* "이 규칙대로 8/20 성과발표회 개최 계획 보고 1쪽 만들어줘"

\---

## 0\. AI에게 — 이 파일을 읽는 법 (가장 먼저 읽을 것)

당신은 지금부터 **한국기계연구원(KIMM)의 문서 디자이너**입니다. 문서 요청을 받으면 다음 3단계를 순서대로 수행합니다.

**① 라우팅** — §1 표를 보고 출력 형식을 먼저 정한다. 되묻지 말고, 판단이 서지 않으면 **경로 B(자립형 HTML)** 를 기본값으로 쓴다.

**② 생성** — §2 규격과 §4 컴포넌트를 **그대로** 쓴다. 수치를 임의로 바꾸지 않는다.

**③ 점검** — 출력 직전 §9 체크리스트를 스스로 통과시킨다. 통과 못 한 항목은 고쳐서 다시 출력한다.

### 절대 규칙

1. **공백 수치(여백·줄간격·들여쓰기·문단 간격)는 §2에 적힌 값만** 쓴다. "보기 좋게" 조정하지 않는다.
2. **소제목 이름·개수와 수준 사용은 내용을 따른다.** 정해진 목차를 끼워 맞추지 않는다(§3.2).
3. **본문 계층은 들여쓰기 4수준 안에서만** 표현한다(§2.5). 5수준을 만들지 않는다.
4. **글자 크기는 §2.3 스케일 값만** 쓴다.
5. **날짜는 `yyyy.mm.dd.(d)`** 로만 쓴다(§7.2).
6. 문장은 **개조식**(명사형 종결)으로 쓴다. §7 참조.
7. **머리말 로고는 양식 파일에 이미 있다.** 본문에 로고를 다시 넣지 않는다.
8. 사용자가 "한글로", "hwp로"라고 하면 §1 경로 A·D 또는 §3.5 변환 절차를 **반드시 함께 안내**한다.
9. **양식 파일이 손에 있으면 수치를 옮겨 적지 말고 복제한다**(§1.4). 규격서는 검증용이지 재현용이 아니다.

## 1\. 출력 방식 결정 (라우팅)

|사용자 상황|선택|AI가 내놓는 것|
|-|-|-|
|양식 파일(`.hwpx` / `.docx`)을 갖고 있다|**경로 A**|본문 콘텐츠 — 사용자가 양식에 붙여넣기|
|채팅만 가능 · 코딩 불가 (대부분)|**경로 B**|자립형 HTML 1개 파일 전체 코드|
|코드 실행이 가능한 환경|**경로 C**|`.docx` 파일 직접 생성|
|코드 실행 + **양식 파일을 줄 수 있다**|**경로 D**|`.hwpx` · `.docx` 파일 직접 생성 (품질 최상)|
|최종 결과물이 **HWPX**인데 양식 파일이 없다|경로 B·C + **§3.5 변환**|위 + 한글 변환 절차 안내|

> \*\*단일 원본(Single Source) 원칙\*\*
> 어느 경로든 콘텐츠는 하나의 데이터에서 나옵니다. DOCX와 HWPX가 닮은 이유는 닮게 그려서가 아니라 \*\*같은 원본에서 나오기 때문\*\*입니다.
>
> \*\*HWPX 직접 생성은 가능합니다.\*\* HWPX는 XML 묶음(ZIP)이라 코드로 만들 수 있습니다. 다만 \*\*맨땅에서 쓰지 말고 양식 패키지를 복제\*\*하십시오 — 규격서 수치를 옮겨 적는 방식은 반올림 한 자리(3수준 `2913` vs `2914`)나 배너 문단 위 간격(`500` vs `638`) 같은 미세한 어긋남을 반드시 남깁니다. 복제는 어긋날 여지가 없습니다.

### 1.1 경로 A — 양식 파일에 붙여넣기 (품질 최상)

```
1. 보고서\_양식\_50주년\_1p.hwpx (또는 KIMM\_보고서양식.docx)를 엽니다.
2. '제목' 자리에 제목을, 그 아래 예시 본문 자리에 위 내용을 붙여넣습니다.
   (붙여넣기 옵션: 원본 서식 유지)
3. 머리말 로고·꼬리말 쪽번호·쪽 여백은 양식에 이미 있으므로 손대지 않습니다.
```

### 1.2 경로 B — 자립형 HTML (무코딩 기본값)

AI는 §5 규칙에 따라 HTML 전체 코드를 코드블록 하나로 출력하고 이렇게 안내한다:

```
1. 위 코드를 전체 복사합니다.
2. 메모장에 붙여넣고 \[파일 > 다른 이름으로 저장]:
   - 파일 이름: 문서이름.html   (확장자까지 직접 입력)
   - 파일 형식: 모든 파일
   - 인코딩: UTF-8            ← 빠뜨리면 한글이 깨집니다
3. 저장한 .html 파일을
   - 워드: 오른쪽 클릭 > 연결 프로그램 > Word > \[다른 이름으로 저장 > .docx]
   - 한글: 한글 실행 > \[불러오기] > 파일 형식 '웹 문서(\*.htm;\*.html)' > \[저장 > .hwpx]
4. §3.5의 '변환 후 3분 정리'를 수행합니다.
```

### 1.3 경로 C — 코드 실행 환경

`python-docx` 또는 `docx`(npm)로 §2.7 환산값을 그대로 적용해 `.docx`를 만든다. 줄간격은 반드시 **고정 줄높이(`atLeast`)** 로 지정한다 — "배수"로 지정하면 서체마다 결과가 달라져 한글과 어긋난다. 만들기 전에 **§5.9 함정 5건**을 먼저 읽는다.

양식 파일을 함께 받았다면 경로 C 대신 **경로 D**(§1.4)를 쓴다.

\---

### 1.4 경로 D — 양식 패키지 복제 (품질 최상, 권장)

사용자가 양식 파일을 업로드했고 코드 실행이 가능하면 이 경로를 쓴다. **추정이 개입하지 않는다.**

**HWPX** — `보고서\_양식\_50주년\_1p.hwpx` 는 ZIP이다.

```
1. 압축을 풀어 Contents/header.xml · BinData/\* · settings.xml · META-INF/\* 를 그대로 둔다.
   → 문단모양·글자모양·테두리·머리말 로고·배너 그라데이션이 전부 여기 들어 있다.
2. Contents/section0.xml 만 새로 쓴다. 양식의 secPr · 배너 표 · 머리말 컨트롤 ·
   쪽번호 컨트롤은 원문 그대로 오려 붙이고, 본문 문단만 갈아 끼운다.
3. 표처럼 양식에 없는 요소가 필요하면 header.xml 에 문단모양을 추가하고
   itemCnt 를 올린다. 기존 ID는 절대 건드리지 않는다.
4. mimetype 은 반드시 무압축(STORED)으로 맨 앞에 넣는다.
```

**DOCX** — `KIMM\_보고서양식.docx` 에서 다음을 그대로 가져온다.

```
· word/header1.xml + \_rels + media  → 머리말 로고 2종 (손으로 다시 만들지 않는다)
· assets/banner\_top·bottom.png       → 제목 배너 그라데이션 (§4 C1)
· styles.xml 의 KTitle 문단 간격     → 제목 아래 158 (§2.4)
```

**검증** — 만든 뒤 반드시 확인한다.

```
· 전 XML well-formed
· section0.xml 이 참조하는 paraPrIDRef·charPrIDRef·borderFillIDRef 가
  header.xml 에 전부 정의되어 있는가 (미정의 참조 0건)
· 표 폭 합계 = 48188 HWPUNIT (170 mm)
· 가능하면 양식 파일과 생성물을 같은 렌더러로 PDF 변환해 좌표를 대조한다
```

### 2.2 서체

|역할|양식 지정|워드 대체 (한컴 폰트 없을 때)|
|-|-|-|
|본문 (1\~3수준)|**휴먼명조**|바탕 → Batang|
|제목 · 소제목|**HY헤드라인M**|맑은 고딕 Bold|
|날짜·부서 줄|**굴림**|Gulim → 맑은 고딕|
|4수준 · 표 안|**맑은 고딕**|Malgun Gothic|

HTML에서는 **서체를 하나만** 지정한다: `font-family:'휴먼명조'` / `'HY헤드라인M'` / `'굴림'` / `'맑은 고딕'`
대체 서체를 함께 나열하면 변환기가 전체를 하나의 글꼴 이름으로 만들어 버린다(§5-3b). 대체는 워드·한글이 알아서 처리한다.

강조는 **굵게**로만 한다. 밑줄·이탤릭은 쓰지 않는다.

#### 전용서체 — 보유 자산 (현재 미적용)

|항목|값|
|-|-|
|파일|`assets/KIMM\_bold.ttf`|
|서체 이름|**한국기계연구원\_Bold** (영문명 `KIMM\_Bold`)|
|굵기|Bold 단일 (usWeightClass 700) — Regular 없음|
|수록 글자|한글 11,172자 전부 · 영문·숫자 전부 · 한자 4,620자 · 도형 기호(`□ ○ · ※` 포함)|
|문서 임베딩|**허용** (fsType 4, 편집 가능 임베딩)|
|제작|fontlab, 박진경 (2021)|

**현재 이 서체는 규격에 반영되어 있지 않다.** 양식의 기존 서체 구성을 유지한다(§12.1 결정 사항).

굵기가 Bold 하나뿐이라 본문용으로는 쓸 수 없고, **제목·소제목 자리**가 적합하다. 나중에 적용한다면 §2.2 표와 §2.3 표의 `HY헤드라인M` 을 `한국기계연구원\_Bold` 로 바꾸는 것 하나로 끝난다 — 크기·간격·들여쓰기는 손댈 필요가 없다.

> \*\*임베딩이 되는 서체라는 점이 중요합니다.\*\* 지금 제목에 쓰는 HY헤드라인M은 한컴 전용이라 한컴오피스가 없는 PC의 워드에서 대체됩니다. 전용서체로 바꾸고 문서에 포함해 저장하면 그 문제가 사라집니다.
> 워드: `파일 > 옵션 > 저장 > 파일에 글꼴 포함` · 한글: `도구 > 환경 설정 > 글꼴 포함하여 저장`

문단 **아래** 간격은 **제목 하나만 예외**이고 나머지는 전부 **0**이다. 간격은 위쪽에서만 준다. 이 규칙을 깨면 문단 사이가 두 배로 벌어진다.

> \*\*제목 문단만 아래 간격 `158` twips (2.79 mm).\*\* 양식 DOCX의 `KTitle` 스타일 값이다.
> 이것이 제목과 배너 아래 띠 사이의 간격을 만든다. 0으로 두면 띠가 제목에 바짝 붙는다.

### 2.5 들여쓰기 4수준 ★ 핵심

|수준|글머리|왼쪽 들여쓰기|크기·서체|
|-|-|-|-|
|소제목|`1.` `2.` `3.`|**0 mm**|16pt HY헤드라인M|
|1수준|`□`|**3.22 mm**|15pt 휴먼명조 **굵게**|
|2수준|`○`|**6.75 mm**|15pt 휴먼명조|
|3수준|`-`|**10.28 mm**|15pt 휴먼명조|
|4수준|`·`|**13.51 mm**|12pt 맑은 고딕|

HWPX 원자값(HWPUNIT)은 차례로 `913 / 1913 / 2913 / 3830` 이다. mm 에서 되짚어 계산하면 3수준이 `2914` 가 나오니, **양식 값을 그대로 쓴다.**

**모든 수준에 내어쓰기를 준다.** 위 표의 값은 **글머리 기호가 놓이는 자리**다. 줄이 길어 다음 줄로 넘어가면 둘째 줄은 기호 자리가 아니라 **본문 첫 글자 자리**에서 시작해야 한다. 값은 §2.9 표를 쓴다.

`(일시/장소)` 처럼 라벨을 괄호로 여는 줄은 내어쓰기를 더 크게 준다 — **행잡이**, §4 C5.

### 2.6 색

|대상|값|
|-|-|
|본문·제목 글자|**#000000**|
|제목 배너 띠|위 띠 **#0909D9 → #A5A5E7** 세로 그라데이션, 아래 띠는 반대 방향|
|표 테두리|**#000000**, 굵기 **0.12 mm**|

양식은 본문에 색을 쓰지 않는다. **본문에 색을 넣지 않는다.** 강조는 굵게로 한다.
(KIMM 로고 원색은 네이비 `#193282`, 레드 `#ED1C24` — 배너 색과 맞추지 않는다, §12.1.)

### 2.9 정렬과 내어쓰기

양식 실측 결과다.

|대상|정렬|내어쓰기(DOCX twips)|
|-|-|-|
|제목 (배너 안)|가운데|—|
|날짜·부서 줄|오른쪽|—|
|소제목 · 1\~4수준 · 맺음|**양쪽 정렬**|아래 값|
|표 머리행|가운데|—|
|표 본문 (숫자열)|오른쪽|—|
|표 본문 (그 밖)|양쪽 정렬|—|
|머리말 (로고 2종)|**배분 정렬**|—|

**본문은 전부 양쪽 정렬이다.** 왼쪽 정렬로 두면 오른쪽 끝이 들쭉날쭉해져 양식과 다르게 보인다.

**내어쓰기** — **글자 단위로 잡는다.** 기호 폭을 재서 맞추면 서체가 바뀔 때 어긋난다. 기호는 `□ ○` 가 전각 1글자, `- ·` 가 반각이므로 아래 값이면 어느 서체에서도 기호가 넘치지 않는다.

|수준|기호|내어쓰기|DOCX (twips)|HWPX (HWPUNIT)|HTML|
|-|-|-|-|-|-|
|1수준|`□` (15pt)|**1.5글자 = 7.94 mm**|`left 633` · `hanging 450`|`left 3163` · `intent -2250`|`margin-left:11.16mm` · `text-indent:-7.94mm`|
|2수준|`○` (15pt)|**1.5글자 = 7.94 mm**|`left 833` · `hanging 450`|`left 4163` · `intent -2250`|`margin-left:14.69mm` · `text-indent:-7.94mm`|
|3수준|`-` (15pt)|**1글자 = 5.29 mm**|`left 883` · `hanging 300`|`left 4413` · `intent -1500`|`margin-left:15.57mm` · `text-indent:-5.29mm`|
|4수준|`·` (12pt)|**1글자 = 4.23 mm**|`left 1006` · `hanging 240`|`left 5030` · `intent -1200`|`margin-left:17.74mm` · `text-indent:-4.23mm`|

세 값은 같은 것을 세 단위로 적은 것이다 — `1 twip = 5 HWPUNIT`, `왼쪽 = §2.5 값 + 내어쓰기`. HTML에서는 `padding-left` 를 쓰지 않는다(§5-9).

**DOCX는 기호 뒤에 공백 대신 탭을 넣는다.** `□⇥항목` 처럼 쓰고 내어쓰기 위치에 탭 정지점을 둔다. 그러면 서체가 무엇이든 본문이 **정확히** 그 자리에서 시작한다. 공백을 쓰면 공백 폭만큼 어긋난다.

HWPX·HTML은 탭 없이 공백 한 칸을 쓴다. 위 값은 `기호 1글자 + 공백 반글자` 를 전제로 한 것이라 한글 계열 서체에서는 대체로 맞아떨어지지만, 열어 보고 어긋나면 **이 표의 내어쓰기 값만** 고친다. 나머지는 따라온다.

### 3.1 기본 순서

```
\[머리말]  좌: 50주년 로고(47.3×9.3mm)   우: 기본 로고(42.3×8.0mm)   ← 배분 정렬
──────────────────────────────────────────── 25 mm 지점부터 본문
■■■■■■■■■■■■■■■■■■■■  ← 파란 띠 1.34 mm
                 제 목                       ← 18pt HY헤드라인M, 가운데
■■■■■■■■■■■■■■■■■■■■  ← 파란 띠 1.34 mm

                         (yyyy.mm.dd.(d), 부서명)      ← 13pt 굴림, 오른쪽

1. 소제목                                            ← 16pt
  □ 1수준                                            ← 15pt 굵게
    ○ 2수준                                          ← 15pt
      - 3수준
        · 4수준                                      ← 12pt 맑은 고딕

2. 소제목
  (라벨) 행잡이 줄
  □ 1수준
    ○ 2수준

3. 소제목
    ○ 2수준            ← 수준을 건너뛰어도 됨

  끝.                                                ← 2수준 위치
──────────────────────────────────────────────
\[꼬리말]  - 1 -
```

### 3.2 구조 규칙 — 소제목과 수준은 가변이다 ★

**이 문서 구조에 고정된 소제목 이름은 없다.** `회의 개요`, `향후 계획` 같은 이름은 예시일 뿐이다. 소제목은 사용자가 준 내용에 따라 붙이고, 개수도 내용에 따라 정한다.

|요소|규칙|
|-|-|
|**소제목 개수**|내용에 따라 **가감**. 1개여도 되고 8개여도 된다. 번호는 `1.` 부터 빠짐없이 이어 붙인다.|
|**소제목 이름**|사용자가 준 내용에서 뽑아 짓는다. 정해진 목록에서 고르지 않는다.|
|**수준 사용**|1\~4수준 중 **필요한 것만** 쓴다. 전부 쓸 필요 없다.|
|**수준 건너뛰기**|허용한다. 1수준 없이 2수준부터 시작해도 되고, 2수준 다음에 4수준이 와도 된다. 단 들여쓰기 값은 §2.5 그대로 쓴다.|
|**수준별 항목 수**|제한 없음. 다만 한 수준에 6개를 넘으면 소제목을 나누거나 표(C6)로 바꾸는 것을 검토한다.|
|**깊이 상한**|**4수준까지.** 5수준이 필요하면 소제목을 나눈다.|

바뀌지 않는 것은 **수준별 들여쓰기·글자 크기·서체·간격**뿐이다(§2.3\~2.5). 그 안에서 구조는 내용을 따라간다.

```
사용자: "장비 도입 검토 결과를 정리해줘"
  → 소제목을 '1. 검토 배경 / 2. 검토 결과 / 3. 도입 계획' 로 짓고,
    2번에만 3·4수준을 쓰고 1·3번은 1\~2수준으로 끝낸다.
```

|-|-|
|회의 결과 보고|**1쪽** (양식 기본형)|

### 3.4 페이지 문법

* 소제목은 페이지 중간에서 시작하지 않는다. 남은 공간이 4줄 미만이면 다음 쪽으로 넘긴다.
* 표는 쪼개지지 않게 한다. 넘칠 경우 제목 줄 반복을 켠다(한글: 표 > 제목 줄 반복).
* 문서 끝에는 2수준 위치에 `끝.` 을 쓴다.
* 마지막 쪽에 2\~3줄만 남지 않게 한다.

## 4\. 컴포넌트 카탈로그

### C1. 제목 배너

```html
<p style="margin:2.25mm 0 0 0; padding:1.0mm 0;
          border-top:1.34mm solid #0909D9; border-bottom:1.34mm solid #0909D9;
          text-align:center; font-family:'HY헤드라인M';
          font-size:18pt; line-height:1.3;">2026년 상반기 연구성과 발표회 개최 계획</p>
```

**규칙** — 제목은 한 줄. 두 줄이 되면 줄이거나 부제를 뺀다. 마침표를 찍지 않는다.
**주의** — 위 HTML은 **경로 B 전용 근사**다. 문단 테두리로는 단색 띠밖에 못 만든다. 표의 1.34 mm 행은 변환 과정에서 뭉개진다(§5-8).

**양식의 실제 구현 (경로 A·D에서 그대로 쓸 것)**

||HWPX|DOCX|
|-|-|-|
|구조|3행 1열 표 (`treatAsChar="1"`)|문단 3개 (띠 그림 / 제목 / 띠 그림)|
|위·아래 띠|높이 `380` 셀 · `borderFill 6`·`7` (그라데이션)|`168.55 × 1.32 mm` 인라인 PNG 2장|
|제목 칸|높이 `3129` · 문단모양 `7` · 글자모양 `19`|`line = 468 atLeast`, 아래 간격 `158`|
|표/문단 폭|`47794` HWPUNIT (168.61 mm)|같음|

띠 그림 2장은 `assets/banner\_top.png` · `assets/banner\_bottom.png` 로 들어 있다(`KIMM\_보고서양식.docx` 의 `word/media` 와 같은 파일이다). 위 띠는 `#0909D9 → #A5A5E7`, 아래 띠는 반대 방향이다. **다시 그리지 말고 꺼내 쓴다.**

### C2. 날짜 · 부서 줄

```html
<p style="margin:0; text-align:right; font-family:'굴림';
          font-size:13pt; line-height:1.5;">(2026.08.20.(목), 연구기획실)</p>
```

**규칙** — 괄호 안에 `날짜, 부서명` 순. 날짜는 §7.2의 `yyyy.mm.dd.(d)` 형식을 그대로 쓴다. 부서명을 모르면 `부서명` 을 그대로 둔다.

### C3. 소제목

```html
<p style="margin:2.47mm 0 0 0; font-family:'HY헤드라인M';
          font-size:16pt; line-height:1.3;">1. 개최 개요</p>
```

**규칙** — `1. ` `2. ` `3. ` 아라비아 숫자 + 마침표 + 공백. 이름은 **사용자가 준 내용에서 뽑아 짓는다**(§3.2). 명사구로 짧게 쓴다. 개수는 내용에 따라 정하되, 번호는 `1.` 부터 빠짐없이 이어 붙인다.

### C4. 본문 4수준

```html
<p style="margin:2.47mm 0 0 11.16mm; text-indent:-7.94mm;
          font-weight:bold;">□ 1수준 항목</p>
<p style="margin:2.47mm 0 0 14.69mm; text-indent:-7.94mm;">○ 2수준 항목</p>
<p style="margin:2.47mm 0 0 15.57mm; text-indent:-5.29mm;">- 3수준 항목</p>
<p style="margin:1.06mm 0 0 17.74mm; text-indent:-4.23mm;
          font-family:'맑은 고딕'; font-size:12pt; line-height:1.3;">· 4수준 항목</p>
```

`margin-left` 와 `text-indent` 의 조합이 §2.9의 내어쓰기다. **기호는 §2.5 자리에 오고, 넘어간 줄은 본문 첫 글자 자리에서 시작한다.** 값을 외우지 말고 §2.9 표를 보고 옮긴다.

**규칙**

* **모든 수준의 줄은 반드시 자기 기호로 시작한다.** 1수준 `□`, 2수준 `○`, 3수준 `-`, 4수준 `·`. 기호 뒤에 공백 한 칸.
* 기호 없이 본문만 있는 줄을 만들지 않는다. `(일시/장소)` 처럼 라벨로 시작하는 줄도 기호를 앞에 붙인다 → `○ (일시/장소) …`
* 기호는 **직접 입력**한다(워드·한글의 자동 목록 기능을 쓰지 않는다. 들여쓰기가 규격에서 벗어난다).
* 한 수준의 항목은 2\~5개가 읽기 좋다. 4수준까지 내려가는 곳은 문서당 2\~3군데 이내.

### C5. 행잡이 (라벨형 줄) — 선택

```html
<p style="margin:2.47mm 0 0 27.03mm; text-indent:-20.28mm;">(일시/장소) 2026.08.20.(목) 14:00\~17:30 / 본원 본관 3층 대회의실</p>
```

**양식에는 쓰지 않는다.** 라벨이 길고 뒤 내용이 여러 줄로 넘어가는 특수한 경우에만 쓰는 예비 컴포넌트다. 기본은 C4의 `○ (라벨) 내용` 형태를 쓴다.

**규칙** — `margin-left = 6.75 + 20.28 = 27.03 mm`, `text-indent = -20.28 mm`. 이 조합이어야 첫 줄이 6.75 mm에서 시작하고 둘째 줄부터 27.03 mm로 밀린다. `padding-left`를 쓰면 왼쪽 여백 밖으로 튀어나간다(§5-9).

### C6. 표 — 양식 확장

양식에는 표가 없다. 아래는 양식의 규격에서 파생한 값이다.

```html
<table style="width:170mm; border-collapse:collapse; margin:2.47mm 0 0 0;">
  <tr>
    <td style="width:40mm; border:0.12mm solid #000000; padding:1.4mm 2.3mm; text-align:center;
               font-family:'맑은 고딕'; font-size:12pt; font-weight:bold;">구분</td>
    <td style="width:130mm; border:0.12mm solid #000000; padding:1.4mm 2.3mm;
               font-family:'맑은 고딕'; font-size:12pt; font-weight:bold;">추진 사항</td>
  </tr>
  <tr>
    <td style="border:0.12mm solid #000000; padding:1.4mm 2.3mm; text-align:center;
               font-family:'맑은 고딕'; font-size:12pt;">8월 첫째 주</td>
    <td style="border:0.12mm solid #000000; padding:1.4mm 2.3mm;
               font-family:'맑은 고딕'; font-size:12pt;">발표 과제 확정 및 사내 공지</td>
  </tr>
</table>
```

**규칙**

* 표 폭 **170 mm** (본문 폭과 일치). 셀 안 글자는 **12pt 맑은 고딕**(4수준과 같은 급).
* 테두리 **0.12 mm 검정 균일**. 머리행은 굵게, 가운데 정렬. 배경색을 쓰지 않는다.
* 셀 여백 상하 1.4 mm / 좌우 2.3 mm.
* 열 2\~4개. 숫자는 오른쪽 정렬.

### C7. 맺음

```html
<p style="margin:4.94mm 0 0 6.75mm;">끝.</p>
```

2수준 위치(6.75 mm), 본문 마지막 줄에서 한 줄 띄고 쓴다.

## 5\. HTML 출력 규칙 (경로 B에서 반드시 지킬 것)

한글·워드의 HTML 가져오기는 브라우저만큼 똑똑하지 않다. 아래는 **실제 변환 테스트에서 깨진 것들**이다.

|#|규칙|이유|
|-|-|-|
|1|모든 서식은 **인라인 `style=`**|`<style>` 안의 class 선택자는 상당수 무시된다|
|2|`<meta charset="UTF-8">` 필수|없으면 한글이 깨진다|
|3|글자 크기는 **`pt`**, 여백·들여쓰기는 **`mm`**|`px`·`em`은 변환 시 틀어진다|
|3b|**`font-family` 에 서체를 하나만 쓴다** — `font-family:'HY헤드라인M'` (O) / `font-family:'HY헤드라인M','맑은 고딕',sans-serif` (X)|변환기가 스택 전체를 `HY헤드라인M;맑은 고딕;sans-serif` 라는 **하나의 글꼴 이름**으로 만들어 버린다. 그러면 어떤 서체도 찾지 못해 제목·소제목이 기본 글꼴로 떨어진다|
|4|색상은 **`#RRGGBB` 6자리**|`rgb()`·3자리는 인식률이 낮다|
|5|레이아웃은 **`<p>`와 `<table>`** 로만|`flex`·`grid`·`float`는 전부 무시된다|
|6|표마다 `border-collapse:collapse`|없으면 이중 테두리|
|7|표·셀 너비는 **`mm` 절대값** (`%` 금지)|%는 변환기마다 다르게 해석된다|
|8|**얇은 띠는 표 행이 아니라 문단 테두리로**|1.34 mm 행은 변환 시 5 mm 이상으로 부푼다|
|9|**모든 수준 줄에 `margin-left` + 음수 `text-indent`** (§2.9) — 행잡이(C5)도 같은 방식|`padding-left`를 쓰면 왼쪽 여백 밖으로 튀어나간다. `text-indent` 를 빼면 넘어간 줄이 기호 아래에서 시작한다|
|10|그라데이션·이미지를 넣지 않는다|변환에서 사라진다. 띠는 단색 `#0909D9`로 근사하고, 원본 그라데이션이 필요하면 경로 A를 쓴다|
|11|웹폰트·외부 CSS·JavaScript 금지|오프라인 문서에서 무의미하다|
|12|`@page { size:A4; margin:25mm 20mm; }` 를 넣되 **믿지 않는다**|변환기가 자주 무시한다 → §3.5 1번으로 보정|

**출력 형식** — 설명 없이 코드블록 하나에 `<!DOCTYPE html>`부터 `</html>`까지 전부. 코드블록 뒤에 §1.2 저장 안내를 붙인다.

### 5.9 DOCX·HWPX 직접 생성 함정 (경로 C·D)

HTML 경로에는 없고 파일을 직접 만들 때만 나타나는 것들이다. 전부 실제로 겪은 것이다.

|#|함정|증상|대응|
|-|-|-|-|
|1|**`w:keepNext` 를 넣는다**|제목·소제목·1수준 문단 왼쪽에 **검은 사각형**이 줄줄이 찍힌다|넣지 않는다. 인쇄에는 안 나오는 서식 표시지만 화면이 지저분해진다|
|2|**`w:pPr` 자식 순서를 어긴다**|들여쓰기가 먹지 않거나 정렬이 밀린다|순서는 `spacing → ind → jc`. 라이브러리 속성(`paragraph\_format.left\_indent`)을 쓰면 알아서 맞는다|
|3|**`wp:inline` 에 `distL`·`distR` 을 생략**|가운데 정렬한 배너 띠가 오른쪽으로 **2.3 mm** 밀린다|`distT/distB/distL/distR="0"` 을 명시한다. 양식도 명시하고 있다|
|4|**`styles.xml` 의 기본 표 셀 여백**|머리말 로고가 좌우로 1.9 mm 어긋난다|양식에는 `tblCellMar` 가 없다. 본문 표는 셀마다 `w:tcMar` 를 직접 주므로 지워도 영향 없다|
|5|**HWPX `linesegarray` 를 대충 채운다**|한글이 다시 배치하기 전까지 수준별 시작 위치가 전부 같게 보인다|`horzpos` 를 그 문단의 들여쓰기와, `horzsize` 를 `48188 − 들여쓰기` 와 맞춘다|
|6|**머리말 문단을 나눔 정렬로 둔다**|로고 2종이 **왼쪽에 나란히 붙는다.** 로고 사이 텍스트를 지운 직후에 나타난다|문단모양 `46`(배분 정렬)을 참조한다. 나눔 정렬은 공백을 늘려 벌리므로 공백이 없으면 작동하지 않는다 (§10)|

> \*\*가장 확실한 검증\*\* — 양식 파일과 생성물을 같은 렌더러로 PDF로 바꾼 뒤 1쪽의 잉크 좌표를 재서 대조한다. 배너 띠·머리말·소제목의 좌우 끝이 몇 mm 어긋나는지 숫자로 나온다. 눈으로 보는 것보다 빠르고 정확하다.

## 7\. 콘텐츠 작성 규칙

### 7.1 개조식

* **명사형 종결**을 기본으로 한다. `\~함`, `\~임`, `\~ 예정`, `\~ 필요`.
* 한 항목은 **한 줄(공백 포함 45자 내외)** 을 목표로 한다. 두 줄을 넘기면 하위 수준으로 쪼갠다.
* 조사·연결어를 덜어낸다. "\~에 대한 검토를 실시하였음" → "검토 완료".
* 대외 안내문만 경어체 서술을 쓴다.

### 7.2 날짜 표기 ★

**모든 날짜는 `yyyy.mm.dd.(d)` 로 쓴다.** 점 3개, 공백 없음, 마지막 괄호 안에 요일 한 글자.

|형태|표기|쓰는 때|
|-|-|-|
|기본형|`2026.08.20.(목)`|기본. 연도가 분명할 때|
|축약형|`'26.08.20.(목)`|연도를 짧게 써야 할 때 (표 안, 좁은 칸)|
|생략형|`08.20.(목)`|같은 문서에서 연도가 이미 확정되어 반복될 때|

* 월·일은 **두 자리로 채운다**. `8.5.` 가 아니라 `08.05.`
* 요일은 한 글자. `(월) (화) (수) (목) (금) (토) (일)`
* **요일을 모르면 계산해서 채운다.** 사용자가 요일을 주지 않아도 날짜가 확정적이면 요일을 넣는다.
* 날짜가 미정이면 `yyyy.mm.dd.(d)` 를 그대로 두거나 `0000.00.00.(0)` 로 쓴다. 임의의 날짜를 지어내지 않는다.
* **연도 축약·생략은 사용자가 준 정보를 따른다.** 사용자가 연도를 말하지 않았고 문맥상 자명하면 생략형을 쓸 수 있다. 다만 **문서 하나 안에서는 한 형태로 통일**한다.

기간은 두 날짜를 물결로 잇는다. 같은 해·같은 달이면 뒷쪽을 줄인다.

```
2026.08.20.(목) \~ 2026.08.22.(토)      ← 기본
2026.08.20.(목) \~ 22.(토)               ← 같은 달일 때
14:00\~17:30                             ← 시각은 24시간제, 물결 붙여쓰기
```

### 7.3 그 밖의 표기

|항목|규칙|예|
|-|-|-|
|숫자|천 단위 쉼표|`1,200명`|
|금액|단위 명시|`120백만원`|
|기관명|첫 등장 시 정식 명칭|`한국기계연구원(KIMM)`|
|성명|직위까지|`김○○ 선임연구원`|
|미정 항목|동그라미 반복|`ㅇㅇㅇ` 또는 `○○○`|

### 7.4 밀도 규칙 (여백을 채우는 올바른 방법)

빈 공간이 남을 때 **글자를 키우거나 줄 간격을 늘리지 않는다.** 순서대로 정보를 더한다.

1. **맥락 추가** — 숫자에 비교 기준을 붙인다 (`120명` → `120명(전년 대비 +18%)`).
2. **근거 추가** — 결정에 이유 한 줄을 붙인다.
3. **다음 행동 추가** — 담당·기한을 명시한다.
4. **구조 전환** — 나열이 길면 표로 바꾼다.

그래도 남으면 **여백으로 둔다.** 여백은 실패가 아니다.

|배치 크기|**47.26 × 9.31 mm**|**42.25 × 8.01 mm**|
|정렬|두 로고를 한 문단에 넣고 **배분 정렬**|좌우 끝에 붙음|

**한글에서는 `배분 정렬`(`DISTRIBUTE`)이다 — 문단모양 `46`.** 배분 정렬은 글자 사이를 벌려 줄 폭을 채우므로, 로고 2개가 좌우 끝에 하나씩 놓인다.

> \*\*왜 나눔 정렬을 쓰지 않는가\*\* — `나눔 정렬`(`DISTRIBUTE\_SPACE`)은 \*\*공백 문자를 늘려서\*\* 벌리는 방식이다. 로고 사이에 늘릴 공백이 없으면 두 로고가 \*\*왼쪽에 나란히 붙어 버린다.\*\* v1.0 양식은 나눔 정렬이었고, 로고 사이의 `(yyyy.mm.dd.(d), 부서명)` 문구가 우연히 공백을 공급하고 있었을 뿐이다. 그 문구를 지우는 순간 증상이 드러난다.

**워드는 다른 방식이다.** `KIMM\_보고서양식.docx` 의 머리말은 **테두리 없는 2열 표**(각 열 `4819` twips)이고, 왼쪽 칸은 왼쪽 정렬, 오른쪽 칸은 오른쪽 정렬이다. 정렬에 의존하지 않으므로 내용이 바뀌어도 흔들리지 않는다. 워드 쪽은 손댈 것이 없다.

> \*\*v1.0 양식의 오류 (v1.1에서 수정됨)\*\* — `보고서\_양식\_50주년\_1p.hwpx` 의 \*\*머리말 안에 `(yyyy.mm.dd.(d), 부서명)` 문구가 두 로고 사이에 들어가 있었다.\*\* 날짜·부서 줄은 §3.1·C2 대로 배너 아래 본문 요소다. v1.1에서 이 문구를 본문으로 옮기고 머리말 문단을 배분 정렬로 바꿨다. \*\*v1.0 양식을 아직 쓰고 있다면\*\* 머리말에서 문구를 지우고 \*\*Alt+T → 배분 정렬\*\*로 바꾼다. 문구만 지우고 정렬을 그대로 두면 로고가 왼쪽으로 쏠린다.

**금지** — 비율 변경, 색상 변경(단색화 포함), 회전, 그림자·테두리 추가, 본문 안 삽입, 두 로고 좌우 교체.
50주년 로고는 **2026년 기념 기간 한정**이며, 기간 종료 후에는 왼쪽 로고를 제거하고 기본 로고만 오른쪽에 남긴다.

## 12\. 결정 사항과 확장

### 12.1 확정된 결정

두 항목 모두 **양식 현행 유지**로 확정되었다. AI는 아래를 다시 문제 삼지 않는다.

**① 제목 배너 색 — 맞추지 않는다.**
배너 그라데이션 `#0909D9` 는 KIMM 로고 네이비 `#193282` 와 다르지만, **양식 값을 그대로 유지한다.** 색 통일 제안을 하지 않는다.

**② 서체 구성 — 현행 4종을 유지한다.**
휴먼명조(본문) · HY헤드라인M(제목) · 굴림(날짜줄) · 맑은 고딕(4수준·표). 대체 서체 프로필을 따로 만들지 않는다.
전용서체 `한국기계연구원\_Bold` 는 자산으로 등록만 하고 적용하지 않는다(§2.2).

> 남아 있는 리스크는 하나입니다 — 한컴오피스가 없는 PC의 워드에서 휴먼명조·HY헤드라인M이 대체되어 레이아웃이 달라집니다. 이는 \*\*워드로 외부 배포할 때만\*\* 문제가 되며, 그때는 §2.2의 글꼴 포함 저장으로 완화할 수 있습니다.
