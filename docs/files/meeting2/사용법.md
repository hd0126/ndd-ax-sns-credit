# 새 PC에서 시작하기 — KIMM Design MD 사용법

> 대상: 이 파일 묶음을 처음 받은 사람
> 준비 시간: 5분 · 코딩 지식 필요 없음

---

## 0. 5분 요약

```
① 압축을 풀어 폴더째 둔다  (파일 위치를 서로 옮기지 않는다)
② 생성형 AI 채팅창에 KIMM-DESIGN.md 를 업로드한다
③ "이 규칙대로 ○○○ 만들어줘" 라고 말한다
④ AI가 준 결과를 양식 파일(.hwpx / .docx)에 붙여넣는다
```

---

## 1. 파일 배치

압축을 푼 그대로 두면 된다. **폴더 구조를 바꾸지 않는다** — 샘플 HTML이 상대 경로로 로고를 참조한다.

```
KIMM-DesignMD/
├─ KIMM-DESIGN.md              ← ★ 핵심. AI에 올리는 파일
├─ 사용법.md                     ← 지금 읽는 문서
├─ 보고서_양식_50주년_1p.hwpx     ← 한글 양식 (머리말 로고·쪽번호 포함)
├─ KIMM_보고서양식.docx           ← 워드 양식 (위 한글 양식과 같은 규격)
├─ assets/
│   ├─ KIMM_logo.png            ← 기본 로고 (머리말 오른쪽)
│   ├─ KIMM_50th_logo.png       ← 50주년 로고 (머리말 왼쪽)
│   ├─ banner_top.png           ← 제목 배너 위 띠 (그라데이션)
│   ├─ banner_bottom.png        ← 제목 배너 아래 띠
│   └─ KIMM_bold.ttf            ← 전용서체 (현재 규격 미적용, 보관용)
└─ samples/
    ├─ sample_개최계획.html      ← 규칙을 적용한 예시
    └─ sample_개최계획.docx      ← 위 HTML을 워드로 변환한 결과
```

권장 위치는 개인 문서 폴더 또는 부서 공유 드라이브다. 공유 드라이브에 두면 부서원이 같은 규격을 쓰게 된다.

## 2. 사전 확인 (1분)

### 2.1 한글(HWP)로 문서를 낼 사람

`보고서_양식_50주년_1p.hwpx` 를 더블클릭해 열리는지 확인한다. 열리면 준비 끝이다. 서체(휴먼명조·HY헤드라인M)는 한컴오피스에 포함되어 있다.

### 2.2 워드(Word)로 문서를 낼 사람

`KIMM_보고서양식.docx` 를 열고 **제목 글씨가 두껍고 각진 서체로 보이는지** 확인한다.

- 정상으로 보이면 그대로 쓴다.
- 밋밋한 기본 서체로 보이면 → 이 PC에 한컴오피스가 없어서 **휴먼명조·HY헤드라인M이 대체된 것**이다. 문서는 정상 작동하며 여백·간격은 그대로다. 서체만 다르게 보인다.
  - 외부로 보낼 문서라면: `파일 > 옵션 > 저장 > 파일에 글꼴 포함` 을 켠 PC에서 만든 파일을 받아 쓰거나, 한컴오피스가 있는 PC에서 작업한다.

### 2.3 전용서체를 설치할 사람 (선택)

`assets/KIMM_bold.ttf` 를 더블클릭 → `설치`. **지금 규격에는 쓰이지 않는다.** 다른 용도(포스터·배너 등)로 쓸 때를 위한 보관 자산이다.

## 3. AI에 규칙 올리기

`KIMM-DESIGN.md` 를 채팅창에 올리는 방법은 도구마다 조금 다르다.

| 도구 | 방법 |
|---|---|
| **ChatGPT** | 입력창 왼쪽 `+` 또는 클립 아이콘 → 파일 업로드 → `KIMM-DESIGN.md` 선택 |
| **Gemini** | 입력창 `+` → 파일 업로드 |
| **Claude** | 입력창 클립 아이콘 → 파일 선택 |
| **업로드가 막힌 환경** | `KIMM-DESIGN.md` 를 메모장으로 열어 **전체 복사 → 채팅창에 붙여넣기** |

### 매번 올리기 번거롭다면

한 번만 등록해 두고 계속 쓰는 기능이 도구마다 있다. 부서에서 상시로 쓸 계획이면 이쪽을 권한다.

- **ChatGPT** — 프로젝트(Projects)를 만들고 파일을 추가하거나, 맞춤형 GPT의 `지식(Knowledge)` 에 올린다
- **Gemini** — Gem을 만들어 지식 파일로 등록한다
- **Claude** — 프로젝트(Projects)를 만들어 지식에 추가한다

등록해 두면 그 안에서 시작하는 모든 대화가 규칙을 이미 알고 있다.

## 4. 첫 문서 만들어 보기

### 4.1 가장 단순한 방법 — 양식에 붙여넣기 (권장)

```
[AI에게]
KIMM-DESIGN.md 를 올린 뒤:

"이 규칙대로 8월 20일 성과발표회 개최 계획 보고 1쪽 만들어줘.
 장소는 본원 본관 3층 대회의실, 정원 120명, 담당은 연구기획실."
```

```
[받은 결과 처리]
1. 보고서_양식_50주년_1p.hwpx 를 연다
2. '제목' 자리에 제목을 넣는다
3. 그 아래 예시 본문(1. 소제목 ~ 끝.)을 지우고 AI가 준 본문을 붙여넣는다
   → 붙여넣기 옵션: 원본 서식 유지
4. 머리말 로고·쪽번호·여백은 건드리지 않는다 (이미 규격대로 들어 있다)
```

워드를 쓴다면 3번에서 `KIMM_보고서양식.docx` 를 쓰면 된다. 두 양식은 같은 규격이다.

### 4.2 파일로 통째로 받고 싶을 때

```
[AI에게]
"이 규칙대로 ○○○ 만들어줘. HTML 파일로 줘."
```

```
[받은 결과 처리]
1. AI가 준 코드를 전체 복사
2. 메모장에 붙여넣고 [다른 이름으로 저장]
   - 파일 이름: 문서이름.html   ← 확장자까지 직접 입력
   - 파일 형식: 모든 파일
   - 인코딩: UTF-8            ← 빠뜨리면 한글이 깨진다
3. 저장한 .html 을
   - 워드로: 오른쪽 클릭 > 연결 프로그램 > Word > [다른 이름으로 저장 > .docx]
   - 한글로: 한글 실행 > [불러오기] > 파일 형식 '웹 문서(*.htm;*.html)' > [저장 > .hwpx]
4. KIMM-DESIGN.md §3.5 '변환 후 3분 정리'를 수행 (여백·줄간격 재설정)
```

`samples/sample_개최계획.html` 이 이 방식으로 만든 예시다. 같은 폴더의 `sample_개최계획.docx` 는 **머리말 로고까지 들어간 완성 형태**이니, 결과물이 어떤 모습이어야 하는지는 이쪽을 먼저 열어 보면 된다.

> HTML 경로는 **머리말·꼬리말을 만들 수 없다.** 로고와 쪽번호가 필요하면 4.1의 양식 붙여넣기를 쓰거나, 변환 후 한글에서 **Ctrl+N,H** 로 직접 넣어야 한다.

### 4.3 파일을 통째로 받기 (AI가 코드를 실행할 수 있을 때)

ChatGPT·Claude 처럼 AI가 코드를 돌릴 수 있는 환경이면, 붙여넣기 없이 완성 파일을 받을 수 있다. **양식 파일을 함께 올리는 것이 핵심**이다.

```
[AI에게]
KIMM-DESIGN.md 와 보고서_양식_50주년_1p.hwpx,
KIMM_보고서양식.docx 를 함께 올린 뒤:

"§1.4 경로 D로 이 내용을 hwpx와 docx로 만들어줘."
```

양식을 함께 주면 AI가 규격을 옮겨 적는 대신 **양식을 복제**하므로, 머리말 로고·쪽번호·배너 그라데이션이 원본 그대로 들어간다. 양식 없이 만들면 이것들이 빠지고 미세한 수치도 어긋난다.

### 4.4 이미 있는 문서를 규격에 맞추기

```
"첨부한 회의록을 이 규칙에 맞는 회의 결과 보고로 정리해줘."
"이 초안을 규칙에 맞게 개조식으로 다시 써줘. 표는 그대로 두고."
"§9 체크리스트로 이 문서를 점검하고 어긋난 부분만 알려줘."
```

## 5. 알아 두면 좋은 것

### 모든 항목 줄에는 기호가 붙는다

`□`(1수준) `○`(2수준) `-`(3수준) `·`(4수준). 기호 없이 본문만 있는 줄은 만들지 않는다. `(일시/장소)` 같은 라벨로 시작하는 줄도 `○ (일시/장소) …` 처럼 기호를 앞에 붙인다.

### 소제목은 정해져 있지 않다

`1. 회의 개요`, `2. 향후 계획` 같은 이름은 **예시일 뿐**이다. 소제목 이름과 개수는 쓸 내용에 따라 정하면 된다. 1~4수준(`□ ○ - ·`)도 필요한 것만 골라 쓰고, 건너뛰어도 된다.

고정된 것은 **수준별 들여쓰기·글자 크기·서체·간격**뿐이다. 그 안에서 구조는 자유롭다.

### 날짜는 한 가지 형식으로

`yyyy.mm.dd.(d)` — 예: `2026.08.20.(목)`
좁은 칸에서는 `'26.08.20.(목)`, 연도가 자명하면 `08.20.(목)` 도 된다. 다만 **한 문서 안에서는 한 형태로 통일**한다.

### AI가 규칙을 어길 때

```
"§9 체크리스트로 다시 점검해줘."
"들여쓰기가 규격과 다른 것 같아. §2.5 확인해줘."
```

규칙 번호를 짚어 주면 대체로 바로잡는다.

## 6. 자주 나오는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 한글이 `???` 로 깨짐 | HTML 저장 시 인코딩이 UTF-8이 아님 | 메모장에서 다시 저장, 인코딩 UTF-8 |
| 변환 후 여백이 이상함 | 변환기가 쪽 설정을 무시함 | 한글 **F7** → 상15 하15 좌20 우20 / 머리말10 꼬리말10 |
| 줄 사이가 너무 넓음 | 줄간격이 기본값으로 바뀜 | 본문 선택 → **Alt+T** → 줄 간격 130% |
| 머리말에 로고가 없음 | HTML 경로로 만들면 머리말이 안 넘어옴 | 양식 파일에 붙여넣기(4.1)로 전환하거나, **Ctrl+N,H** 로 로고 삽입 |
| 머리말 로고 2개가 왼쪽에 붙음 | 머리말 문단이 **나눔 정렬**이라 늘릴 공백이 없으면 벌어지지 않음 | 머리말 안을 클릭 → **Alt+T** → 정렬을 **배분 정렬**로. v1.1 양식은 이미 적용되어 있다 |
| 제목 위아래 파란 띠가 사라짐 | 그라데이션이 변환에서 손실 | 양식 파일에서 배너 부분만 복사해 교체 |
| 워드에서 서체가 달라 보임 | 한컴오피스 전용 서체가 없음 | 2.2 참고. 여백·간격은 정상이므로 그대로 써도 무방 |
| 제목·소제목만 기본 글꼴로 보임 | AI가 HTML의 `font-family` 에 서체를 여러 개 나열함 | AI에게 "§5-3b에 따라 글꼴을 하나만 지정해줘" 라고 요청 |
| AI가 매번 다른 형식을 줌 | 규칙 파일을 안 읽었거나 대화가 길어져 잊음 | 파일을 다시 올리거나, 프로젝트/Gem에 등록(3장) |

## 7. 다른 사람에게 전달할 때

이 폴더를 **통째로** 압축해 보낸다. `KIMM-DESIGN.md` 만 보내면 양식 파일이 없어 4.1 방식을 쓸 수 없다.

규칙을 고쳤다면 `KIMM-DESIGN.md` 의 §12.3 형식으로 한 줄 남긴다. 무엇을 왜 바꿨는지가 남아야 다음 사람이 되돌리지 않는다.

---

*문서 규격 자체에 대한 모든 내용은 `KIMM-DESIGN.md` 에 있다. 이 파일은 그것을 쓰기 시작하는 방법만 다룬다.*
